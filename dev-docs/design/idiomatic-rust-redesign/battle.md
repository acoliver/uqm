# Keep the ordered arena. Change who owns a battle tick.

UQM already has checked entity identities, owned graphics and sound resources, and an explicit packet codec. The next migration should keep those. Its main job is to give each fact one writer. Today, changing a ship's energy can mean decoding its descriptor, calling a drawing service and copying the result back. Changing one field on an element can clone two visual states and commit on `Drop`. A fleet index can mean a species, a place in a sorted catalog, a screen slot or an ordinal among living ships. These problems survive a line-for-line translation into safe Rust.

Start with the crew/energy path and the ordered arena interfaces. They reach actual gameplay, have visible outcomes, and can eliminate old code as soon as their callers move. Do not start by replacing the pool, introducing an ECS, or turning all callbacks into end-of-frame events. An earlier collision callback can change which callback runs next, and the AI allocates from the same finite pool as real weapons.

## Where the game actually goes

1. **Construction.** `engine/src/lib.rs:27`, `modes/src/lib.rs:5`, `content/src/lib.rs:12` export different parts of battle. `E/mod.rs:1` reexports modules that `E/access.rs:497,763` owns via `#[path]`. The real `Kernel` comes from `engine/src/kernel.rs`, reexported by `E/record.rs:709`. `rust/src/app/mod.rs:24` installs primitive and race services, the input runtime, options and the **application's** ship lifecycle. The startup loop at `rust/src/mainloop/lifecycle_abi.rs:44` loads species 1 through 25 into `master_native::engine::load_entry`. It does not call the mutex-backed `H/catalog.rs:98` loader.
2. **Entry.** The app enters `S/native/menu.rs:274` from `rust/src/app/runtime.rs:80`. The menu admits catalog choices, files, graphics and network state. `S/native/menu/live/battle.rs:91,114` confirms peers and delay, lends the picker frames, chooses a gravity well with a random draw, installs the menu's network handle, calls `B/battle_native.rs:419`, then releases those loans and clears inputs. Campaign entry uses `B/encount_native.rs:554` with temporarily replaced controls and sound bank. The flight caller at `rust/src/mainloop/lifecycle_abi.rs:72` supplies a per-frame clock/radar callback. Preserve all three uses of the loop.
3. **Tick.** `B/battle_native.rs:96,196,288` attaches a protocol session even when no peer is present. Per frame: obtain frame number, optionally checksum before input, poll, process local sides before network sides and ships in queue order, flush, verify delayed checksum, invoke the optional frame callback, advance through `redraw_queue`, handle exit flags, pace, observe and advance the protocol frame. Drawing is conditional; simulation is not. An aborted frame need not produce the normal completion checkpoint. Ship selection order via `E/input.rs:51` is a different rule from input order via `B/battle_native.rs:20`.
4. **From selection to an effect.** `B/ship_native.rs:208` loads a battle descriptor through `H/loader_native.rs:6` and `H/races/mod.rs:34`, attaches it, allocates or reuses an element and inserts a new ship at the head. `B/ship_native.rs:78,169` resolves species processing and weapon callbacks through `E/access/record_ops.rs:72`. Species use engine projectile, statistics and tracking operations; mode services return to UI, sound and death handling. `E/weapon.rs:28,56,81` and `B/process_native.rs:360` meet in the same element arena. Neither a detached shot prediction nor a real shot implies unbounded storage.
5. **Death and return.** `B/tactrans_native.rs:197,305,469` gates replacement on battle-end/ditty state and installs transition behavior. `B/context_access/reader_legacy.rs:5,30` calls the appropriate picker and maps the ship's fleet position to the persistent fragment. The installed `rust/src/game_init/space_resources.rs:13,48` counts floating crew, detaches descriptors, recovers crew, unloads assets, writes back for a non-aborted encounter and completes deferred reset. `B/encount_native.rs:483` handles salvage, rewards, removal and story accounting. Melee returns to the retained menu and peer session, not a fresh setup. The similarly named functions in `H/lifecycle.rs` and `H/writeback.rs` operate on a different model.

## Findings: engine and battle modes

### 1. Make the live record the mutation API

`E/record.rs:20,44` stores an element and a ship. `E/access.rs:224` returns value projections. `E/record.rs:216,271,300,370` decodes and reapplies them; `E/views.rs:135` clones the edit value on drop. A velocity or flag write can therefore touch unrelated frame handles and hooks. `B/ship_native.rs:49` uses several successive guards to initialize one ship. `B/element.rs:120,178` defines yet another full element, including primitive, hooks, intersection and visuals. It even starts a new element with a different player default than the live record. The latter type is used by tests and projections; do not adopt its defaults wholesale. `B/mod.rs:33` exposes competing models through glob exports. `E/access/schema.rs:5` puts a game clock, fuel and autopilot in a battle module despite their world lifetime.

Store the fields as the domain values downstream actually need: motion, current/next pose, role/lifecycle, allegiance, target and optional owner. Start by embedding a directly borrowable group in the live record. Read by reference, mutate a field or group with a short borrow, end it before dispatch. Reserve an owned `Subject` for a prediction that really needs independent state. Make observer/fixture DTOs one-way reads. Use separate bit sets for independent flags and an enum for genuinely exclusive states; do not make `APPEARING`, `PRE_PROCESS` and every other bit mutually exclusive. Name crew versus object health, and thrust wait versus blast offset at the point their roles are known. Keep the exact projection of these bytes for CRC. Move world schema to its owner and remove path remapping as each definition becomes private to one module. No new facade with one getter per C field.

### 2. Keep order and bounded allocation, remove the pointer API

`C/pool.rs:10,66,76,170,195,260` already implements typed IDs with owner and generation checks, separate allocation/linkage, checked disjoint pair access, insertion, and LIFO free reuse. Removal leaves neighbor information available until free. `E/table.rs:8,33,85,296` rebuilds a second key from slot, checks generation again, exposes raw addresses and scans up to 150 slots for addresses or sound tokens. `E/link_queue.rs:12,65,78` adds another key and erases whether a borrow was shared or exclusive: `DerefMut` on the shared case panics. These are different problems from the need to visit a live list in a repeatable order.

Wrap the pool's typed key in a domain ID where side or ordering differs. Preserve element comparison by slot then generation where currently observed; do not derive a new ordering that puts pool serial first. Provide an immutable ordered iterator, explicit mutation methods on the owner, and a short-lived cursor or explicit successor lookup for callbacks that can mutate the list. Keep `Option` on allocation failure, assert on foreign IDs where the caller has promised ownership. Express detached, linked, and retired operations separately at least at the module API. Pass an `ElementId` to positional sound until the audio adapter needs a token. Move journal address translation out of live lookup. A ship unlinked by a load inside a callback can remain allocated through battle cleanup (`E/record.rs:716`); eagerly freeing all unlinked values would break that contract. Do not replace ordered identity with `HashMap` iteration, `swap_remove`, or a vector of IDs collected at the start of the tick.

### 3. Put gameplay changes before presentation under a single writer

`E/statistics.rs:34,47` sets low-energy status, counters and element hits but delegates the descriptor update to `draw_statistics`. `B/services.rs:14` copies ship info, calls `ui::shipstat::update_statistics`, then writes crew and energy back. A substitute presentation service can change the simulation. Meanwhile `E/access/record_ops.rs:36` treats primitive kind/color as the cloak predicate, and `B/weapon_native.rs:14` draws silhouettes. Assets, colors and geometry still affect battle rules. Merely putting drawing on another thread would change behavior.

Give the combatant an operation returning an accepted/refused/dead outcome and a before/after HUD delta. Commit changes once, pass that delta by value to the existing synchronous presenter at the original call site. Keep original-vs-current crew for clamping, negative-energy refusal, the final-battle NPC exception, flash timing and relative order with sound. For cloaking, introduce one named visibility predicate from the existing style first. Move toward an explicit cloak stage only when Ilwrath targetability and its rendered transition match on every step. Keep actual frame-mask intersection as an explicit input to simulation. Adapt `E/services.rs:6,21`, `E/race_services.rs:13` and `B/race_services.rs:19` into small capabilities for damage presentation, replacement, navigation and audio. The installed dependency direction is useful; passing `&mut Cx` back to a presenter for authority over all game state is avoidable.

### 4. Own battle admission and lifecycle in the calling mode

`E/context.rs:5,69,134,147` splits `Battle`, `World` and `Kernel`, but exposes all three mutably, an RNG function, optional solar state and a raw kernel escape. `with_context` makes a fresh battle even when a caller only needs world services. `E/input.rs:65` permits `Network(None)`; `B/battle_native.rs:96` finishes wiring it later. `battle` returns `count < 0`; elsewhere `0`, `1`, signed counts, activity bits and a boolean drive different caller decisions. `B/context_access.rs:72`, `context_access/navigation.rs:82` extend the same context with mode, status and navigation work. `B/lifecycle.rs:15,89,141` describes frame/teardown stages and a refcount model, but `do_battle` and application lifecycle drive the actual game. `B/integration_tests_p14.rs:14` is not evidence that those model states govern a live encounter.

Have the caller construct a `RunningBattle` borrowing the game-thread arena, the admitted inputs and a local or connected match driver. Keep persistent fleets, images and protocol outside this borrow when they must survive a match. Separate `BattleExit` (completed, fled, load, abort, as required by callers) from admission errors and a loop's `Continue` decision. Model instantaneous victory and single-ship admission explicitly instead of inferring them from a signed count. Validate control method at decoding/configuration, then construct `NetworkInput` only with a peer. Provide a scoped override for campaign controls and a frame callback that borrows only the world/IO it needs. Do not introduce an engine trait for every pure function. Delete duplicate phase models after moving any independent tests to the live transitions. Keep `gendef.rs:3`'s existing delegation to planet identities; import from the actual owner instead of adding battle definitions.

### 5. Make tick phases explicit without delaying mutations

`B/process_native.rs:234,360,561,658,787` is both scheduler and renderer. Candidate preprocessing may kill the active projectile. Some contacts restart at the head; recursive checks search for earlier impacts with `time_value - 1`. Contact can realign frames before retrying. The successor is captured **after** preprocess on the main pass, **before** retiring a disappearing item, and **after** postprocess for a survivor. Postprocess encounters newly inserted items without the pre bit, processes that suffix and stops applying the original camera scroll. `B/process_native/invoke_collision.rs:22` and `dispatch.rs:15,62` select order and reload the second hook and parent after the first. Cached candidate pairs or a global deferred spawn list would change these cases.

Give an ordered `advance_frame` distinct operations for prepare, earliest contact, resolve pair, update view, commit/retire, and emit batch. Return a contact outcome instead of either zero or a mask. Keep the bounded list walk and recursion until tests cover its restart points. If stack depth merits change, model the suspended operation explicitly and compare the full call trace before replacing recursion. Isolate pure `collision_motion.rs:19,78` and `queue_view.rs:29,136` math. Camera settings can change in a hook, so sample them at the same point (`queue_view/tests.rs:47`). Keep `process_native/dispatch`, `invoke_element`, `invoke_collision` as one semantic dispatch operation, not three places to add logging. The purpose is to make the scheduling rule legible, not to reorder by phase name.

### 6. Separate draw order, audio queue and their retained resources

`E/display.rs:7,34,68` has 330 slots and deliberately retains non-link primitive fields when slots return. `display/primitive.rs:8,38` overlays point/stamp/line origins by convention and selects shape from a public byte. `DisplayPool::batch` constructs an order vector, then a second command collection. `B/galaxy.rs:49,382` sorts star planes with a specific equal-Y swap order and rotates a sorted start index on wrap. A stable sort with an arbitrary tie key is not a drop-in replacement. `E/kernel.rs:7,18,54,90` maintains parallel sound/source arrays, four LRU channels and per-plane arrays. `B/sounds.rs:56,76,97` retains the sound clip through playback, handles positional source retirement and caps admission at eight. Silence fills the admission budget rather than behaving like an empty queue.

Keep retained `FrameArray`/`FrameSelection` and borrowed `FrameRef` (`E/frames.rs:19,251,337,377`), the batch of owned drawing commands, and context/font leases. Restrict mutable primitive style to named kinds/operations. Retain inactive shared-origin/frame data wherever a later kind switch actually reads it. Build the command batch directly in a single ordered iteration; keep background-reverse then element order. Use a bounded queue of `QueuedSound { clip, source }` and a separate silenced state; keep reuse of same channel before idle search then LRU. Keep camera and parallax rules independent of the backend, including fixed-width projection, frame skip, and stepped versus continuous scaling. `B/status_native.rs:70,120,367`'s border, turn animation and successive explosion flash phases belong in a presenter. `E/hyperspace.rs:11,23`'s palette/context lifecycle belongs with navigation graphics. Neither needs authority to change ship stats.

### 7. Give behavior a name independent of a function address

`E/hooks.rs:6` wraps native functions in single-variant enums; `E/race.rs:12,25,100` has a useful immutable behavior definition, per-instance state and default/disabled/override selection. The latter distinction matters. But `E/access.rs:237`, `E/race_ops.rs:15` record `(function address, parent address)`; `B/tactrans_native.rs:164` compares addresses to determine behavior; even application teardown recognizes `new_ship` by address. `B/hook_registry.rs:15` resolves linker-folded machine functions with a species prefix and lexical tie breaker. `H/hook_registry/{assigned,races}.rs` and `B/hook_registry/ships/core.rs` maintain separate address/name lists. This is architectural coupling to the linker, even with zero unsafe dereferences.

Give an installed action a stable semantic ID plus a typed callable, declared together by its owner. Use explicit states for transition, explosion, crew and resurrection predicates used by gameplay. Static functions remain suitable for distinct species behavior. Avoid a boxed trait object per projectile or a giant match duplicating species implementations. Preserve the old trace names in an observer mapping and the before-call event timing. Then remove address tests, name disambiguation, marker functions whose sole job was trace identity, and manual registries. Migrate the consumers in teardown and AI, not just the logger.

`C/observation.rs:16,31,78,94` puts a process-global event log, frame count, saves and pool/token allocator in collections. `observe_views` builds a vector and role string before the `enabled` check in `record`. `E/access/observe.rs:25,65,96` reconstructs address/pred/succ views; `E/observation.rs:5` already has useful value-only observations. `B/context_access/{observe,fixture}.rs` project live records for automation. Keep stable trace identity across retirement/reuse **as the trace currently defines it** (slot address and allocation lifetime are distinct); deliver it via an optional per-run sink. Keep process-wide uniqueness where two pools or simultaneous games require it, separately from observation. Make disabled tracing lazy. Move fixture mutations behind the test/automation boundary and distinguish a journal key that can outlive an entity from a live ID.

### 8. Improve the algorithms where their outputs permit it

`M/mod.rs:70,89,111,127` contains both a global relaxed load/compute/store Park-Miller stream and an independently owned `RandomContext`. An atomic read plus a later store does not provide independent game streams. `E/context.rs:69` injects only the draw function. `N/checksum.rs:46` reads the global seed by swapping in zero then restoring, bypassing that injection. First use a non-advancing peek on the same stream; then let the game own a single RNG value across setup, selection, battle and return. Do not seed a new stream on entering each context. Preserve seed coercion, campaign time fallback versus melee seed zero, negotiated seed admission, byte extraction, retry loops and draw order. Last Pkunk voice is also process-global (`E/kernel.rs:3`, `H/races/pkunk_native.rs:156`); keep the shared history across ships within one game and its descriptor initialization/reset point. Two independent games should not affect each other.

`M/battle_types.rs:109,144,169,190`, `M/mod.rs:12,161,249,267`, `M/velocity.rs:13,89` provide overlapping trig and wrap helpers with *different result widths*. Keep signed narrowing points, north at angle zero, 64 angles, 16 facings, zero-vector special case, one-step wrap and half-extent ties. Keep the velocity error accumulator; predicting movement on a copy must not advance live motion. The two-width hand-coded integer square root is a candidate for `u32::isqrt` only after differential vectors around perfect squares, both paths at 65536 and extremes. Use `Facing`, `Angle`, named world/display/velocity conversions, and a per-axis stepper with an explicit projection of its packed bytes. Do not replace integer arithmetic with trigonometric floats or indiscriminately widen intermediates. Compare table values before sharing implementations. Migrate content-local helpers, including `H/native.rs:16`, only for matching width contracts.

`E/motion.rs:18,43` already separates acceleration policy; `E/intercept.rs:20,132` separates swept rectangle broad phase from frame intersection. Keep these separations. Return `Option<ContactTurn>` at the domain boundary instead of overloading zero. `E/gravity.rs:11,71` mixes a query for a gravity source with ordered acceleration side effects; split callers by intent while preserving `mass.wrapping_add(1) > 100` and current/next selection. `E/tracking.rs:25,32` mutates a facing out-argument and returns a signed delta with -1 for no target. Return a tracking value carrying target, facing and optional delta. Preserve explicit-target precedence, zero-distance behavior, comparison order, and a single random draw only on opposite headings. `E/projectile.rs:6`, `weapon.rs:28,56`, `world_elements.rs:9,59` have good local arithmetic but use generic element fields for many roles; introduce constructors for laser, missile, rubble, crew and asteroid, with explicit allocation/link points. Planet spawn retries until gravity and matter checks succeed; moving random draws before a failed allocation or batching spawns changes the stream.

`B/ai_entry.rs:17,36` routes human escape, random pick and tactical AI; `context_access/ai_legacy.rs:20` converts count plus slice to a fixed array and back. `E/cyborg.rs:109,146,508` scans elements in link order, works on a `Subject`, evaluates concern slots in reverse, applies enemy weapon tie rules and restores facing. It also creates real temporary weapon elements, tests them, and disposes of the unused suffix on a hit. `E/ai_constants.rs` and `B/ai.rs:28,68` encode indices and movement/rating flags in multiple types. Keep the projected subject, but use named concern slots plus a bounded active range and `Movement` enum. Model simulated shot lifetime explicitly; never assume an independent scratch arena can succeed when the real pool is full. Remove duplicate pure dispatch/flag formulations once all fixture users call the live decisions. Profile full-arena cases before adding a spatial index: stable nearest/tie order, allocations, and frame masks constrain what it could replace.

## Findings: content, identity and fleets

### 9. Keep one species definition and one asset owner

`EN/species.rs:3,38,68` describes three numbering systems as integer constants. Conversation Arilou and campaign ship Arilou are 0; live descriptor Arilou is 1. Campaign Sa-Matra aliases the drone ship number in one domain; the descriptor factory has distinct boss and noncombat probe entries. `S/types.rs:39` starts the melee list at Androsynth, uses 255 for empty and 254 for unset. `H/types.rs:28` defines another species type. A cast between any two of these can produce a valid but wrong ship. Give each namespace its own type; use exhaustive conversions or a catalog lookup and reserve raw integers for save, wire, assets and trace adapters. Use `Option<Species>` or lifecycle state where 0 denotes a retired ship. Keep explicit aliases at the boundary that defines them.

The live factory at `H/races/mod.rs:34` searches a list of 28 `(id, &Race)` pairs. `H/code_resources.rs:2` panics on an unknown raw ID; `H/loader_native.rs:6` returns `None` for either unknown species or asset failure. `E/template.rs:8,35`, `descriptor.rs:5`, `record.rs:693` and `ship_assets.rs:139` build a descriptor containing immutable definition, mutable stats, behavior overrides, padding, resource names, loaded owners and raw aliases including a pointer-to-pointer victory ditty. Battle versus metadata is a boolean passed to both load and unload. `E/androsynth_template.rs:25` and `vux_template.rs:9` put two content definitions inside the engine. The mode can observe a descriptor already attached to a ship even if subsequent element allocation fails (`B/ship_native.rs:208`). That failure path needs an explicit owner until cleanup.

Use a closed `Species` lookup yielding a content-owned `ShipDefinition`, with separate construction of instance state (including campaign-dependent SIS and Shofixti configuration). Move those two templates to their races. Separate `CatalogAssets` from `CombatAssets`; return `Result<LoadedShip, ShipLoadError>` with species, role and resource identifier for a missing required asset. Keep optional icons optional and retain the navigation-only campaign probe transfer. Keep resource owners, borrowing for callers that do not retain and cloning leases for those that do. Spell out gameplay cleanup that needs `World`; do not try to run world mutations from `Drop`. Remove padding/alignment, mirror keys and raw aliases only after identifying and migrating every raw consumer. A byte fixture or address-normalized observation is not itself evidence of a required in-process ABI.

`H/master_native.rs:12,32,62` inserts live descriptors by the bytes of string entry 2, after existing equal names, then traverses the linked catalog even for indexing. Keep this ordering and the incremental startup/yield schedule. A bounded sorted vector and a species-to-catalog-index lookup would suit 25 mostly immutable entries; insert stably, expose borrowed entries and explicit retained picker assets. The metadata-only mirror uses hardcoded abbreviations and a global `Mutex<Option<Vec<_>>>` (`H/catalog.rs:37,72`); its order is not the authority for a loaded catalog. The second registry (`H/registry.rs:29,997`) has 28 sets of stats and zero resource IDs. Its text golden checks formatted debug output. `H/c_bridge.rs:11,81` aliases all handles to `usize`; its registry backend panics on actual resource requests. `H/loader.rs:40,123` manually deduplicates frees and rolls back a descriptor, but a failure loading the second or third size can precede assignment of the first handle into that descriptor. This is a risk for a nonzero bridge, not a claim of a leak in the live game. Move relevant failure and alias tests to the live loader rather than extending the second loader.

`H/queue.rs:76,137,186,431`, `lifecycle.rs:56,115,281`, `writeback.rs:67,213,384` implement a parallel fleet on vectors, numeric indices, a global mutex and separate fragment records. Some operations already take slices, iterators or an explicit RNG closure. Move captain naming and escort rules that actually have users; e.g. `rust/crates/modes/src/front_end/gameopt/preview.rs:60` calls `pick_captain_name`. Compare survivor writeback, infinite fleets, retries and name uniqueness against the actual application paths before deleting this family. `H/native.rs:4`'s bounded NUL-terminated name copy is appropriate for a byte buffer at that boundary; it need not define a second native math API.

### 13. Keep the codec and transport, shrink the protocol state surface

`EN/network.rs:1` contains no live socket code. `network/loopback.rs:11,45` implements the host `Net` contract with a small shared in-memory bus. It already distinguishes pending, FIFO bytes, partial reads, `WouldBlock`, peer EOF after draining and broken pipe. `local_port` is unsupported here. Keep this deterministic test transport and test the socket adapter against the same observable contract where applicable. A scripted short-write transport can add coverage without giving the in-memory bus timing dependencies.

`N/packet.rs:4,26,58,146` explicitly encodes all 18 protocol 0.4 packets. This is a justified external representation. Keep big-endian length, kind and payload words, reserved bytes zero on output, variable fleet/name padding, byte names, and decode-one plus consumed length. Do not serialize Rust struct layout or substitute a new serialization format. `Packet::encode` panics on oversized constructed frames; enforce a bounded outbound payload or return an encode error at construction. `N/netrcv.rs:144` has a 2048-byte receive budget; distinguish incomplete frames that can still fit from a full buffer that cannot make progress. Preserve the peer-visible disposition when replacing it. `N/packetq.rs:24` preserves a partial front offset, but re-encodes and allocates the bytes on a later flush. Encode the current front once, advance its cursor, count it once on completion. Preserve interruption retry, backpressure, zero-write error and FIFO. `rust/tests/netplay_codec_fixtures.rs:5` checks exact bytes and every proper prefix, stronger evidence than a new-code-to-new-code round trip.

`N/session.rs:13,88` uses a retained `Rc<SessionCore>` with `RefCell` for each connection, transport, input, CRC and selection. Options require unique `Rc` ownership to mutate. `N/netconnection.rs:35,46,92` combines `NetState`, booleans for parallel exchanges, generation counters, optional sockets and ready continuations. `N/packethandlers.rs:21,45` checks ordinal state ranges and flags before dispatch. `E/net.rs:38,45` gives a protocol driver a useful borrow for notices/waits, but `BattleNet` also exports setup, selection, frame counters and shutdown through the same object. `N/netmelee.rs:16,95,181` and `netwait.rs:51,67,123` use fresh borrows across waits. For example, `wait_connections` counts peers disconnected **before** each wait and discards the closure's negotiation result. Characterize a disconnect during the wait before changing what the boolean means.

Model the per-peer ready, confirmation/cancel and reset exchanges explicitly under the phases where they exist. Use named state predicates instead of relying on enum ordering. Keep independent exchanges independent; a giant flat enum enumerating every combination would be harder to validate. A peer transition should consume one packet or local action and return effects *and* acceptance/rejection. On invalid fleet input, earlier entries can already have produced effects. Do not make rejection drop all effects. `N/netrcv.rs:12,29` releases the connection borrow before effects; on seed it emits before setting `random_seed`; on end it flushes the frame count before installing the next ready stage. `N/netconnection.rs:224`, `N/driver_tests.rs:40,77,133` cover reset and notice ordering. Effects can close the peer. Process them before the next packet and recheck the peer by ID. Keep the menu as protocol owner across battles; let selection and lockstep borrow only their operations. Retain `Rc` where synchronous reentry truly needs shared ownership, without exposing `Deref<SessionCore>` and `RefMut<NetConnection>` to every caller. Keep `N/notify.rs:9`, `ready.rs:3`, `state.rs:6`, `native/menu/live/boundary.rs:77` as setup/encoding or UI adapters rather than additional protocol authorities.

Preserve protocol version checks, side translation, the 35-frame delay limit, 14 slots, ID 255 for empty, truncated remote names, and reset exceptions. Characterize the native-byte conversions for Ping/Ack and Abort at `N/packethandlers.rs:72,117` against the fixture peer before any endian cleanup. A packet word's byte order and the simulation checksum's field byte order are different contracts. Keep malformed-input errors distinct from normal disconnects internally even when the same existing notice is emitted.

### 14. Make lockstep a single frame contract

`N/battle.rs:45,70,102,138` implements the engine protocol boundary. `N/netinput.rs:18,29` preloads *each* FIFO with `delay` zero inputs and admits up to `2 * delay + 2`. `N/checkbuf.rs:8,21` uses cyclic storage indexed by interval, initialized with zero. `N/packethandlers.rs:214` bounds the accepted frame window. `N/mod.rs:22` sets checksum interval to 1. Preserve modulo behavior, accepted window, zero-initialization semantics and verification at `frame - delay`. Introducing `Option` for missing checksums may be a behavior change if a zero currently compares equal. Make an initialized `DelayWindow` owned by the running match. Use named `FrameNo` and negotiated delay; never call index on a default uninitialized checksum ring.

`B/netplay.rs:52,129,191` contains `CrcState` and a second input/end/sync model over the modes `Element`. `N/crc.rs:3` wraps the CRC; `N/checksum.rs:9,31,46` projects the *live* fields. Keep one CRC accumulator and one checksum projection consumed by gameplay and automation (`rust/src/automation/parity_state/live.rs:7`). In exact order: seed, then linked non-background elements; flags, life, hits, mass, turn and thrust, velocity angle and vector/fract/error/incr extents, current and next positions. Use little-endian CRC integer feeds. Exclude resource IDs, parents, colors, RNG draws and image references. Eliminate repeated element/image cloning just to checksum scalars. Keep packet checksum words big-endian on the wire. Test a nonempty scene and a background-only change, and compare the full input and reset timeline of two consecutive battles in one session.
