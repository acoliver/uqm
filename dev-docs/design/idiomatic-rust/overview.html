UQM: from C-shaped Rust to idiomatic Rust

The uqm crate under rust/ at main 0ba2845ad. Summary of architecture.md, quality-gates.md and plan.md, with the design review findings (summarised in plan.md section 6) already applied. The PRs are listed in work-items.md; agents follow AGENTS.md.

Verdict Today the game is about 218k lines of Rust that still has the shape of the C it was ported from: 375 static mut globals, Rust modules calling each other through 1,922 extern "C" functions, and 23% of production lines inside unsafe. The target is an owned Game passed as &mut into per-mode sessions, battle elements in an order-preserving pool addressed by generational ids, races and planet generators as traits, and unsafe only in the platform layer. The single package becomes six crates whose dependency graph lets the compiler enforce the layers; each crate splits off once its code stops reaching upward, starting with the save format in Phase 0 and the former C library layer in Phase 1. The work runs as nine phases and 63 PRs, starting with a battle-core pilot, and every PR must reproduce a deterministic replay byte for byte and pass save round trips, the native failure scenarios and shrink-only xtask gates. Game behaviour, the save file format and the netplay wire format and checksum do not change.

2Architecture

Now

Rust modules call each other through the linker. Almost every foreign declaration resolves to a #[no_mangle] definition in this same crate; the only external native code is SDL2, libc sockets and macOS frameworks. State lives in shared static mut globals that any module can reach.

Future

Layers with one dependency direction. app owns one Game and one Platform and passes them down as &mut. Each mode creates its session on entry and drops it on exit. Only platform touches native code.

Crates

Today 25 of the 37 top-level modules form one cycle through crate:: paths, and 364 of 371 cross-module foreign declarations are statics such as GlobData. Cargo rejects cyclic packages, so a crate can split only once its code stops reaching upward. Modules move with git mv, keep their paths and are re-exported by the root, so a split is a mechanical PR.

What blocks each split, with file and line, is in architecture.md section 2.2. The former C library layer reaches the game through only 13 paths and 7 foreign statics, which one PR inverts before the move. Per-mode crates, a separate automation crate and graphics or sound crates were considered and not adopted: none would enforce a rule the six crates do not.

The game logic runs on one thread today (CreateThread_Core has no caller; the other threads are audio and automation I/O), so an owned &mut Game needs no locks. Entry points take what they use, for example fn battle(game: &mut Game, io: &mut Io<'_>, kind: BattleKind) -> Result<BattleOutcome, GameError>. The call graph and statement order stay the same; only the way state is reached changes.

Two alternatives were rejected. A thread_local! RefCell<Game> fails at run time because collision callbacks re-enter (collision, then death, then spawn), so a second borrow_mut panics. Wrapping the statics in an UnsafeCell with a "single thread" rule leaves aliasing unchecked by the compiler, which is the problem being solved.

Some code already has the target shape and is left alone: planet_side/, the savegame codec, dialogue scripts, the planet generator logic in planets/generate/orz.rs, mainloop/state_machine.rs and the sound command enum.

3Data layout: element queue to ordered pool

The pool reproduces C order by following the queue's rules:

  • Allocation. InitQueue frees slots N down to 1 (collections/queue.rs:110-114), so allocation hands out 1, 2, 3 and reuse is last-freed-first. The pool does the same, and exhaustion at MAX_DISPLAY_ELEMENTS = 150 behaves as before.
  • Links. put appends like PutQueue, insert_before matches InsertQueue, remove unlinks without freeing.
  • Traversal. There is no snapshot iterator. Loops call head() and succ(id) at the same point C reads the successor, so elements appended by a callback during a pass are visited in that pass.
  • Records. The five bindgen unions hold same-typed members and become one field each with named accessors. pParent: *mut c_void becomes enum Parent { None, Ship(ShipId), IpGroup(Id<IpGroup>) }. image.farray becomes a FrameSetRef that names its owner (a ship and role, or a shared set such as blast), so Arilou's "is this my special" test becomes an equality on owners.

5Migrating without breaking the game

Race files, hyperspace and IP flight read element records directly through raw pointers, so the storage cannot be swapped in one step. Each shared authority changes in three stages, and no stage keeps a second copy of any state.

Stage B has five rules: storage is never moved, so a raw element pointer is valid until its slot is freed; pointers handed to legacy code derive from the static's address, never from a Rust reference; converted code holds no record reference across a call into legacy code; nested entry goes through app::bridge, which holds at most one published context and panics if entered with none; and no synchronisation step may be added, because there is only one copy.

Proving behaviour is unchanged

  • V1, deterministic replay. uqm --replay <scenario> replaces the three sources of variation that seeds alone leave open. A replay clock moves only when the game sleeps (no real sleep happens). ReplayAudio runs the sound command enum on the game thread and answers track and position queries from replay time, so speech ends on the same step every run. Scripted input is consumed at input admission, by count. The trace has one line per input, simulation step and present, carrying the unchanged netplay CRC, a state digest of every element, ship and story field, and a canvas digest. A golden is committed only when three recordings are byte-identical: macOS, ubuntu CI, and a run with random 0-20 ms sleeps under CPU load.
  • Corpus. Nine replays (four Cyborg-vs-Cyborg melee fleets covering all 25 melee ships, human-input melee, campaign battle, Sa-Matra, hyperspace, solar flight, lander, comm, new game) plus eight short fixtures for the hard cases: hook swap (Androsynth), reincarnation (Pkunk), pred-walking point defence (Chmmr), death that spawns mid-pass, converted-hits-unconverted collision, pool exhaustion at 150, frame-set identity, and hyperspace star contact with save and reload. Refactor PRs may not change goldens; a deliberate behaviour fix is its own PR with the parity-golden-update label.
  • V2, native scenarios. Lander destroyed, out of fuel, lost battle and Super Melee on a real macOS window.
  • V3, saves. Codec round trip for the 73 saves in rust/scripts/saves/ plus legacy-save.00. A runtime test loads each save under replay mode, enters the saved mode, and compares a live capture with the Phase 0 golden. Load and save are not inverse operations, so the normalisations the current code applies are listed as data.
  • V4, campaign reload. The 45 load-* scenarios and the smoke set, run natively at each phase exit with OS screenshots inspected.

PR rules: one work unit per PR (a queue, module, session or group of races), with the old path deleted in the same PR; mechanical moves and semantic changes in separate PRs; 500 to 3,000 changed lines, mechanical moves larger; tests move with the code; nothing is deleted before its last consumer moves. The critical path is 34 of the 63 units; the rest run in parallel lanes over 36 waves (work-items.md).

Shrink-only baseline. Existing debt lives in one file, rust/xtask/quality-baseline.toml, written only by xtask. A value above its entry fails, and a new violator with no entry fails. A value below its entry prints a notice; cargo xtask quality --tighten rewrites the file downward in one command, and phase-exit PRs run it. With --base, each PR is also measured against the base branch tree, so headroom freed by an earlier PR cannot be spent later.

Debt transfers. Moving a function or file to its new layer would otherwise look like new debt. cargo xtask quality move <old> <new> records the move; it is accepted if the old key existed at base and is now gone, each source credits one target, and no crate total rises. Any other growth needs the quality-growth-approved label, which only you apply. Setting the legacy_hooks and bridge_calls budgets in the first two Phase 1 PRs is one such approval.

Not adopted: crate-wide clippy pedantic, and 60-line or cognitive-15 limits, which would force splits of functions that mirror one C function and make side-by-side review against the original harder.

Why battle first. The hardest part of the design, exact C ordering with re-entrant callbacks, lives in battle; ships and Super Melee depend on its interfaces; and it has the strongest oracle (netplay CRC plus the state trace, from a menu with a fixed seed). Starting with Super Melee would mean converting its battle calls twice. Planet generators would prove little, since their logic is already safe. GlobData touches 111 files and would fix an access pattern before any pattern is proven.

8What stays the same on purpose

  • Fixed-point arithmetic and C integer widths, including wrapping_* operations and narrowing casts. Type aliases may be renamed (Count = u16) but not widened.
  • Statement order in ported functions, including RNG draws and sound queueing, even where idiomatic code would reorder them.
  • The save format: packed layout, LZH compression and chunk order, including the writer's element-amount quirk.
  • The netplay wire format, NETPLAY_PROTOCOL_VERSION and the sync checksum, byte for byte.
  • Dialogue as code (Dialogue<A: Api>), data tables, race descriptor constants, string-table indices and resource names.
  • Scenario JSON in rust/scripts/ and the automation scheduler's contract: input admission, simulation checkpoint and committed present stay three separate hooks.
  • Traceability: functions drop CamelCase when they stop being exported and keep a /// C: <name> (<file>.c) doc line.
