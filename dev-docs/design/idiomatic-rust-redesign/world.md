# World, runtime and exploration: Rust design audit

Pin: [`678f8c11defe28a85cfccac29899410209e9963c`](https://github.com/acoliver/uqm/tree/678f8c11defe28a85cfccac29899410209e9963c). Static inspection only. Paths below use `E/` for `rust/crates/engine/src/`, `R/` for `rust/src/`, `M/` for `rust/crates/modes/src/` and `C/` for `rust/crates/content/src/`. Line numbers refer to this pin.

**Recommendation:** Keep one game-thread campaign owner, keep the save representations, and replace one complete player action at a time. Start with startup failure and lander trip settlement: both have explicit failure returns that skip cleanup. The calendar, replay clock and presentation loop need separate contracts. Combining all three behind a new `Runtime` or putting `World` behind a mutex would hide who can advance time and commit game state.

Start at the executable. `R/main.rs:15-50` parses before platform installation, installs the replay or normal platform before content checking, and exits help/version/check-content without entering the game. `R/main.rs:87-106` constructs one Game, shares its activity and configuration handles and the same input controls with optional automation, runs Application, then finalizes the observer. A replacement must keep early-exit side effects separate from normal startup and preserve the identity of those handles when restarting a game. `R/main.rs:161-184` makes evidence-finalization errors affect process status. A replay that finishes gameplay but fails to write its summary must not report success.

Exploration crosses `M/mainloop/restart_menu`, `M/navigation`, `M/planets`, `M/planet_side`, and `C/planets/{tables.rs,generate/}`. Directory inclusion means inventoried, not line-reviewed. No build, test, native run or save/replay comparison was requested or performed. Behavioral tests below are proposed gates, not passing evidence.

## What runs, and which owner must survive it

### Launch, configure, enter, leave

**Two option models are visible; only one feeds `main`.** `R/cli.rs:11,149-151` defines the derive parser and a merge into `R/config.rs:5`'s `Options`. `R/lib.rs:9-17` exports both. That model defaults to 640×480 and its file loader returns defaults without reading a file (`R/config.rs:86-103,128-134`). The binary calls `R/mainloop/options.rs:428-445`: parse once to find mode/config directory, read `uqm.cfg` only for normal mode without a parse error, then apply CLI overrides. Its default is 1280×960 (`:34-35`). `:452-490` reads text from the OS and accepts typed `BOOLEAN`, `INT32`, `STRING` lines; `:526-539` scales integer gamma by 1000 and volumes by 100. A test of `Cli::merge_into_options` says nothing about what settings the executable supplies. No production caller of that merge surfaced in the Rust source search; public consumers outside the repository were not checked.

`R/mainloop/dir_prep.rs:136-162` resolves CLI directory before environment before platform default, exports `UQM_CONFIG_DIR`, creates and mounts it. `R/mainloop/content.rs:16-46,50-57` makes bad explicit content fatal, searches packaged layouts before cwd otherwise, and actually decompresses `uqm.rmp` for the smoke check. These calls use `std::env`, `std::fs` and paths directly. The comment in `main` about platform-mediated files does not describe all startup I/O. Even help can probe for content when no path is supplied (`options.rs:439-443`); no SDL or save directory is needed for that probe. Retain the distinction between read-only discovery and mounting/writing directories.

**Process startup owns devices; campaigns borrow them.** `R/app/mod.rs:14-45` installs the content catalog and injects the native input runtime, options menu, battle services, ship lifecycle and save slots into the supplied game. `R/mainloop/startup.rs:29-47,51-81,85-125,129-185` starts SDL and records the game thread, installs the VFS, applies sound/input/preferences, prepares config/content/melee/save and addon shadows, then starts graphics and input. `E/configuration.rs:8-67` holds preferences, content path and addon list behind a cloneable `Arc<Mutex<Values>>`. A clone shares changes, but a `Preferences` read is a copy. Applied device settings have other owners: `E/configuration/runtime.rs:33-86` captures the actual video mode, audio and config directory, and applies display changes by flushing, stopping video, reinitializing and flushing. Consumers include `M/mainloop/restart_menu/restart_ops.rs:409` and `M/front_end/setupmenu.rs:204-218`. Do not replace this with a cached preferences read that lies about applied display or audio state.

`R/app/runtime.rs:35-71` creates one `Battle`, borrows `World` and `Kernel` in a `Cx`, initializes audio, loads kernel, shows splash, calls restart, and loops campaigns. The splash's “background” callback loads species with cooperative yields and then initializes the kernel (`R/mainloop/lifecycle_abi.rs:44-70`); it is synchronous here. `R/game_init/kernel_abi.rs:13-42,49-87` opens display/resources, loads indices, optional voice/addons and palette, then fonts/status/text/sounds/space and contexts. Preserve the fallback from requested to unavailable speech (`using_speech=0`). `R/game_init/cleanup.rs:6-35` separates campaign assets from space, fonts, contexts and resource system; `R/mainloop/teardown.rs:10-17` uninitializes input/audio/graphics **before** clearing dispatch, removing VFS and retiring the thread. `R/app/runtime.rs:15-32` calls that teardown after `run_game`, including returned errors, but not after failed startup. This matters for retry and for callbacks queued against resources being released.

### Campaign state, kernel services and observation

`E/world.rs:27-69,120-185,292-303`: `Game` already owns a `World` and a `Kernel`. `WorldData` contains the flagship and game record; `World` adds selected star, packed story, queues, state files, clock, encounter data and retained fleet assets. Queue façades give fleet/built/NPC/group/encounter capacities 24/12/14/32/16 and ordered typed links. `E/kernel.rs:102-172` combines game-lifetime services and configuration with scene caches, display contexts, lander assets, battle elements, audio channels and player input. `E/kernel.rs:173-255` has both installed resource owners and borrowed leases; a raw frame ID is not a lifetime guarantee. A meaningful split follows `game_init/cleanup.rs`'s release sites. Moving fields between bags without moving their users and their releases has no benefit.

`M/navigation/globals.rs:51-82,97-143` resolves species templates against the master catalog, separately retains the probe, initializes group and planet files, and supplies names, human race, initial Sol position and activity to `World::new_game`. `E/world/new_game.rs:37-45,92-124` first resets data and clears canned nodes, runs the preparation closure on the reset world, then clears global flags, reinitializes queues, installs equipment, prices, names, one escort and the autopilot sentinel. `next_activity` is outside the value reset; the restart menu clears it at a different boundary. Preserve this ordering and deliberately specify which data persists through load, restart and a second campaign. `E/world.rs:242-283` clears star selection on catalog replacement, retains catalogs with `Rc`, and derives a `StarId` by checking the address of a descriptor within that particular array. Equal descriptor values in an unrelated allocation do not identify a star. Propose carrying a checked index from lookup instead; retain catalog order and sentinel entries (`:326-329`).

**Story bytes are a format contract.** `E/state/game_state.rs:1` reexports the implementation; `E/state/game_state_keys.rs:1-11` delegates to World. `E/world/story.rs:19-111,136-196` operates on inclusive bit ranges, byte buffers and separate 32-bit fields. `E/state/ffi.rs:14-69,79-117` normalizes legacy arguments, snapshots the source for overlapping bit copies, errors on snapshot without a story and can install bytes before any new game. These are safe Rust functions despite the filename. `E/world.rs:188-215` offers a different convenience contract: missing story reads as zero, absent writes are ignored, and `u32` narrows to `u8`. `M/planet_side/session_factory.rs:71-79` reads actual upgrade keys through that route. Preserve packed layout and save chunk semantics at the codec, distinguish “no campaign” from a legitimate zero inside the game, and prevent callers passing a wide field to a byte accessor. Test neighboring bits and an unaligned 32-bit round trip before removing raw helpers. A state file is also data: `E/world/state_file.rs:208-306,331-351` manages in-memory files, positions, byte replacement and little-endian words. `M/navigation/groups.rs:68-159` encodes fixed 268-byte headers and 16-byte records. Hash the result or compare bytes, not Rust struct size.

`E/world/activity.rs:8-48,51-55,230-247` has one atomic 16-bit word, with a low-byte mode and high-bit signals. The cloned control can read it and `fetch_or` flags, returning the **preimage**. The game-thread owner can store a whole word. This is much narrower than sharing `World` with a worker. `R/app/lifecycle.rs:5-45` evaluates story/crew, resolves load or zeroes velocity, mutates the word before dispatch, re-reads it on encounter completion and records the *returned* word as `kernel.last_activity`. `R/mainloop/state_machine.rs:107-121,159-197,231-305` owns these decisions; `R/app/runtime.rs:128-168,171-212` runs their effects, including Black Ur-Quan comm, clears restart only after recording, and chooses 30 vs 5 seconds per campaign day for solar vs battle. Do not make a pre-dispatch snapshot determine post-dispatch load/abort or death. `R/app/lifecycle.rs:61-128,164-189` contains useful production-helper tests for those boundaries, not proof of a complete restart.

`E/observe.rs:35-101` captures from the invoking `Cx`: fleet and group link order, active groups only, counters, retained ship facing, and hyperspace readiness based on a live solid player element. Velocity alone cannot say whether transition has finished. `from_world` alone deliberately lacks battle/kernel values (`:103-128`). `R/automation/observer.rs:91` uses `for_input`, which only builds the full view for selected admissions. `E/observe_port.rs:70-78,89-142` separates admission/injection, checkpoints, simulation and presentation, with a no-op `Unobserved`; admission takes a mutable `Cx`. `R/mainloop/input_driver.rs:5-39,64-70,100-137` pumps async and input, admits before/after update, runs menu sound/hook/frame then completes the frame; either admission may stop it. `R/mainloop/input_frame.rs:33-68` presents entry to a nested loop and each completed draw transaction, including the terminating callback, before the simulation notification. Preserve a side-effect-free no-observer path and never publish live `World` references to recorders. Compare nested first frame, final frame and checkpoint order, not just final activity.

### Host services, three time domains, callbacks and threads

| Domain | Who advances it | Contract to retain |
|---|---|---|
| Elapsed milliseconds and presentation ticks | `E/host/clock.rs:23-46` reads elapsed host milliseconds as `u32`; `E/time/counter_abi.rs:8-24` scales to 840 ticks/second. `E/host/clock.rs:68-88` advances replay only on a wake, never on a read, counts steps and reports a busy-read loop with the call site. | Distinguish milliseconds from `TimeCount`. Reads must not advance simulation. Repeated or overdue replay sleeps still reset the read guard. |
| Cooperative alarms, input and frame pacing | A **platform** owns `Dispatch`, despite the “one game” comment. `E/host/platform.rs:121-136` supplies the clock to it. `E/graphics/highlight.rs:521` arms a real alarm. `R/mainloop/input_driver.rs:12-15` services work at input boundaries. `E/threading/pacing.rs:132-163,244-271` distinguishes absolute vs relative sleeps and replay vs native. | For native sleep-until, run async work then pump/flush even when overdue; measure remaining time *after* flushing and cap sleep at the next alarm. Native relative sleep just flushes then sleeps. Replay processes work, flushes, advances the clock and advances the sound stream. Don't silently make the paths identical. |
| Campaign calendar and dated events | `R/app/runtime.rs:90-99` starts a game clock on the World and schedules initial events. `E/time/clock_bridge.rs:42-69,74-116` starts paused on 2155-02-17, uses 24 base ticks per second of day rate, rescales remaining ticks on rate change and rolls one day at expiry. `R/mainloop/lifecycle_abi.rs:7-9` and `M/planets/solarsys/flight.rs:440` drive `M/navigation/events.rs:75-104`. | Delivery is tied to campaign ticks, not elapsed host sleeps. Advancing N days must run each intervening day's events, then reset the tick count. `E/clock/mod.rs:5-32,48-78` fixes 18 slots and saved selector IDs 0–17. Keep count/order and field widths through a save/load. |

`E/host/platform.rs:16-61,64-97` defines display, input, disk, audio, workers/system, networking and clock access behind one install-once `Platform`. Access before installation panics in the ordinary build; tests/test-support get a real-time fallback. `rust/crates/platform/src/lib.rs:27` installs the implementation. In `rust/crates/platform/src/host.rs:25-69,73-119,124-139`, replay uses scripted input, silent output and its own clock, but still has OS disk, network, system, joystick initialization and display opening. A replay is neither an isolated filesystem nor proof of native device behavior. Keep the OS choice at composition. Supply the clock/dispatch pair to the frame owner rather than making every domain accept a platform with all capabilities. Test missing install in the production configuration separately from an injected test host.

`E/callback/mod.rs:75-122,132-204` drains a bounded FIFO round; work queued by running callbacks waits for the next round. It runs callbacks outside the queue lock, lazily removes cancelled alarms, runs a due alarm then another callback round, and returns 1 ms for pending callbacks versus `u32::MAX` for no work. Clearing drops tasks and tombstones without resetting ID counters. Equal-deadline *host alarms* compare only by deadline (`:33-47`); do not assume the stable same-date order of *campaign events*. `E/time/clock_abi.rs:18-64,87-124` inserts equals after existing events, executes zero relative delay immediately, declines past dates, unlinks a due/overdue event before dispatch, and frees its slot **after** dispatch. `None` can mean immediate delivery, full pool or past date. `M/navigation/events.rs:114-145,240-284` shows why it matters: the Arilou entrance sets the opening flag and schedules exit; the daily encounter advances fleets, conditionally rolls an encounter and reschedules itself. Preserve selector order and the RNG draw sequence alongside queue bytes.

`R/time/mod.rs:6` reexports the live bridges. Separately `:133-155,181-239,253-298` defines another public `GameClock`/`SharedGameClock` with `BTreeMap<GameDate, Vec<Event>>`, a 100-tick default, incrementing elapsed ticks and nested mutex ownership. `move_days(days)` calls `tick()` once per requested day and drops its returned events. With the default rate, `move_days(1)` leaves the date unchanged; contrast actual play at `M/navigation/events.rs:95-104`. Treat this as a defect in the exported model, not a claim that in-game time skips are broken. Remove the competing model after checking consumers, not the `time` bridges used by the application.

`E/threading/game_thread.rs:9-49` registers the SDL owner by thread number; `yield_task` polls events only on that thread and yields without flushing. `E/threading/affinity.rs:6-16` captures a thread identity for comparison. `E/sync.rs:3-15` panics on a poisoned `std` mutex; real users include `E/bridge_log.rs:28,43` and the pacing stats lock at `E/threading/pacing.rs:192-216`. That policy is not universal: replay clock explicitly recovers a poisoned guard (`E/host/clock.rs:60-65`) and callback queues use their own lock type. Keep owner-affine graphics local; pass owned work to workers and handle external failures at the boundary. Do not add a shared World lock to implement thread safety.

### From restart to a saved planet visit

**Restart.** `R/mainloop/mod.rs:32` reexports the modes implementation. `R/app/runtime.rs:57-69,76-87` supplies real `RestartServices` for melee, credits and campaign asset cleanup. `M/mainloop/restart_menu/restart_ops.rs:24-92,94-150` binds a large operations trait to a retained graphic, context, overlay, font, batch and music. `do_restart.rs:77-135,137-181,185-239` initializes the first frame before selection, times inactivity at 120 seconds with music or 20 without, paces at 30 Hz, signals ready, and distinguishes setup, new, load, melee and quit. `orchestration.rs:62-155,179-215,230-262` handles bomb death, victory credits, clearing history, resource destruction, `0xffff` attract timeout, melee re-entry and intro cancellation. New and load both enter interplanetary; last activity distinguishes them. Nonzero automated seed overrides clock seeding (`restart_ops.rs:16-22`). Keep these separate outcomes and selection across a nested setup/return. Test a second visit with an actual retained `RestartMenu`, input runtime and `Unobserved`, not just a mock vtable. `owned_tests.rs:24,116,144` already exercises some production operations in isolation.

**Travel.** `M/battle/race_services.rs:186` calls `M/navigation/hyperspace.rs:43-98`. Movement clips logical coordinates, writes back actual displacement, corrects the player element, accumulates distance and debits the SIS gauges only on the fuel-consuming side. Fuel uses integer rounding and carries a remainder when the 8-bit tick accumulator rolls over. The live debit (`:27-40`) requires the status context and tiny font, tying travel to drawing. `M/navigation/hyper_transition.rs:104-149,152-185` installs temporary ship hooks and a non-solid flag, restores hooks at matching facing, distinguishes a loaded appearance, and conditions star selection/entry on movement and autopilot. That same readiness is visible to the observer. `M/navigation/hyperspace.rs:105-181` walks fleet *order*, checks actual strength, sphere and special encounter eligibility, consumes a random draw only after the spatial checks, and queues by race. A map keyed only by species would lose the separate rebel slot. For IP play `M/navigation/interplanetary.rs:155,419,554` handles group preprocessing, collisions and missions; group persistence is shared with orbit entry/exit. Test clipped movement, zero fuel, QuasiSpace, portal-gated collision and re-entry from a save using the same geometry and RNG inputs.

**System and orbit.** `R/app/runtime.rs:199-210` calls `M/planets/solarsys/lifecycle.rs:535-553`: recover/select star, allocate a local `SolarSystem`, initialize graphics/flight, borrow it into the synchronous input loop, uninitialize, clear `solar_frame`, publish `Solar(None)`. `M/planets/solar_system.rs:26-46,49-65,87-111` captures catalog position and descriptor identity separately, supplies content's planet table and a visit RNG, and keeps outer/inner location, selected body, orbit status and drawing resources. Persistence encodes planet as moon 0 and moon i as i+1, but saved orbit uses 1 and i+2 (`E/world/generation.rs:16-44`). `M/planets/solarsys/lifecycle.rs:271-355` reads retrieved masks, invokes orbital generation, checks resulting load/abort/encounter/death/story before opening a submenu, and reconstructs the flight display only on an ordinary return. `:583-593` chooses orbital vs non-orbital save. Preserve a visit's captured star when campaign selection later changes.

**Content is executable behavior as well as tables.** `C/planets/tables.rs:69,602` supplies the ordered catalog and planet types; `M/planets/mod.rs:10-13` reexports them and generation. `M/planets/solarsys/site/dispatch.rs:12-53` observes, lends a reborrowed `Cx` and `Io` through `RefCell`s, dispatches by the visit's content index and applies input effects before observing again. `C/planets/generate/mod.rs:50-85` selects a stateless `SystemGenerator`, sharing implementations for ranges (e.g. Melnorme) and falling back to default for unlisted indices. Default layout/scan takes an explicit RNG via `E/world/generation.rs:101-126,158-186`; default orbital analysis calls back to load the presentation (`C/planets/generate/generator.rs:20-71`). `generate/host.rs:16-49` requires many unrelated story/encounter/report abilities even for a layout-only call. Preserve the data tables and default behavior. Narrow the effectful operations at one generator's call sites; a new trait for every star would repeat the problem.

For a concrete oracle use Sol. `C/planets/generate/sol.rs:168-218` reseeds for nine planets, consumes default moon draws **before** overriding Earth moons, and takes another draw for Luna's angle. Save the next RNG value as well as the generated descriptors. `:230-265,280-306` has conditional energy nodes and ten Luna life nodes. A Pluto pickup that survives the crew-loss sequence sets `FOUND_PLUTO_SPATHI`, reports, starts takeoff and returns *false* so the node remains visible during takeoff. Luna's report and takeoff precede setting both moonbase flags; it returns *true*. A generic `bool = success` adapter or deferred batch of all story writes would change play. Sol and the default dispatch were sampled; the presence of a generator directory or a zero-sized-generator test is not proof of that species' plot behavior.

**Lander trip.** `M/planets/scan/live.rs:238-297` suspends the underlying input callback, charges gravity-based fuel, runs a synchronous trip, then either redraws orbit or starts the Pluto encounter. `M/planet_side/ffi.rs:63-86,94-149` borrows owners, asks for optional admission/fixture and retains assets/scan masks. `session_factory.rs:25-68` computes the ship delta and applies a crew debit only after checking landers and crew. `ffi.rs:152-220,245-260` wires the production collision, graphics, audio, clock and ship adapters, polls only in Active phase, runs `runtime::run_frame_at` and attempts failure settlement. The trip silences menu sounds via a guard. `runtime.rs:16,212-245,312-355` distinguishes transition, return and destruction frames from active simulation at the lander cadence (35 Hz). `collision_adapter.rs:302` commits resolved contacts; `generation_adapter.rs:140,224,313` ties persistence to retrieval masks, the story dirty flag and canned nodes. `ffi.rs:113-129,296-309` publishes a terminal result or a typed failure with operation/batch correction information. A fixture may supply entities via production admission; success there does not prove unassisted planet generation or normal keyboard control.

## Replacement units and when the old code may go

Write the boundary test first in each unit. Migrate the production caller, its error path, observer and tests together, then delete the superseded route in that same change. These are proposed cuts around player actions. They do not require a new crate or an engine-wide interface hierarchy.

1. **Launch through first menu, including failed launch.** Let argument discovery return `Launch::Help | Version | CheckContent(path) | Play(settings)`; parse the CLI once into explicit overrides, merge only for Play. A `StartedServices` owner should acquire mounts/devices/dispatch in order and unwind only what it owns. Build required navigation assets locally before publishing them to `Kernel`; keep optional assets explicit. Drive both `--check-content` and normal startup from temporary config/content trees. Check CLI > file > default, addon shadow order, unavailable speech, unsupported gamma, teardown/retry and exit status. **Delete when:** `main`, setup menu, root exports and in-repo users all use one option schema; remove redundant `R/cli.rs`/`R/config.rs` model and `ParsedOptions` conversions that have no user. Replace success integers and partial-init sentinels on this path with one error result. Keep other kernel resources untouched. Check public library/API consumers before removal.
2. **Orbit → launch → pickup → return or destruction.** Make `begin_trip` return an owned debit record with an explicit terminal state; consume it once in `finish_trip`. Separate admission failure, abort, returned cargo and lander loss. Apply committed gameplay effects once; later presentation errors must not reapply or reverse them. Keep retained assets, menu-sound lifetime and 35 Hz timing. Use actual `run_session` and the same `run_frame_at` as production with a failing device port. Include a run without fixtures; compare observed vs unobserved ship and scan state. **Delete when:** there is one crew/lander accounting path, no compensation via `outcome.is_ok()`, no stale callback after transitions, and pickup/scan work with the same generator implementation in tests and play. Remove the replaced `Cffi*` pass-throughs only where direct borrows or typed adapters serve all callers.
3. **New/load → dispatch → restart.** Keep a typed `CampaignTransition` and a small restart outcome (`New`, `Load`, `Melee`, `Quit`, `Attract`) at the app boundary. Retain history recording, bomb/victory special cases and activity preimage; convert raw flag encodings at save/observer boundaries. Bind the restart drawing/music lifetime to its input loop. Use two campaign starts on one Application plus a second independent World. Assert last/next word, velocity, queues, story bytes, fleet/probe leases, observer identity, input selection and seed. Exercise menu → melee → menu and cancelled intro. **Delete when:** production restart and dispatch no longer exchange false/`0xffff` as a menu result, and individual `RestartMenuOps` get/set/draw trampolines and mock-only scaffolding have no users. Keep `ActivityValue`/packed state where the saved representation needs it; do not replace it with a differently encoded enum on disk.
4. **Flight through one midnight and a save/load.** Put calendar record, ordered event operations and rate conversion behind a per-campaign calendar API, e.g. `schedule(...) -> Immediate | Queued(id) | Past | Full`. Keep encoded fields and IDs at the serializer. Separate `travel_step` (clipped displacement, fuel delta, encounter effects) from status drawing; feed it the same geometry/RNG. Test an ordinary star and a vortex, Hyperspace and QuasiSpace, saved facing, fractional day on rate switch, leap-day, same-day FIFO, recursive zero-delay and an Arilou open/close cycle across load. Compare next draw, not only final position. **Delete when:** battle frame, solar flight, move-days and saves use the same calendar; eliminate unused root `GameDate`/`GameClock`/`SharedGameClock`, duplicate conversion functions and redundant bridge entry points once callers and public surface are accounted for. Do not delete `E/clock`'s save selector table or conflate campaign days with host alarms.
5. **Present and pace one input frame.** Give the game-thread frame driver narrow clock, event pump, dispatch and present capabilities with typed ticks/ms. Move stats onto the driver, or borrow them only while updating samples. Keep real/replay backends and a no-op observer; separate frame admission commands from immutable observations. Record a nested menu from entry to its terminating callback: expected sequence includes initial present, before/update/after, hook/frame, present then simulation; repeat with pre-update stop, post-update stop, due alarm adding callbacks and overdue flush. **Delete when:** live native and replay loops share the specified boundaries, callbacks cannot outlive owner teardown, workers cannot pump the display, and no obsolete `now`/sleep/observe forwarding entry points or second frame runner remain for that slice. One OS installation can remain for subsystems not migrated; avoid adding a second global dispatcher.
6. **Visit one solar system, scan and save its changes.** Split layout/scan from story effects for default and Sol first. Pass `StarId` (catalog slot), content identity, `Body` and the correct RNG deliberately. Model pickup results as retrieval disposition plus ordered effects rather than a generic success bit. Commit planet masks to the selected location before clearing the dirty flag. Keep fixed tables and special site behavior. Test seeded Sol layout, Earth moons, ordinary-world minerals, canned biological nodes, Pluto crew loss/interruption and Luna report/takeoff. Orbit scan must consume **no** gameplay draw; fresh biological population consumes one per eligible node (`M/planet_side/generation_adapter.rs:36-66,245-292`). Compare successive save bytes and the next encounter after revisit. **Delete when:** scan, lander and orbital call sites all use the same typed generation path for migrated identities, with no `cfg(test)` substitute; then retire those `SiteHost` supertraits and `RefCell<Cx>` forwarding methods with zero callers. Do not remove a species implementation or promise equivalent special plots from a Sol-only run.
