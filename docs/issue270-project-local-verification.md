# Project-local verification scratch

Issue #270 exposed two independent path assumptions during RenderTopography verification. The supported xtask route staged executables in `/var/tmp`, regardless of TMPDIR. Two workflow transport fixtures bound Unix sockets below temporary evidence directories whose complete names exceeded Darwin's `sun_path` capacity.

Executable staging now uses `tmp` beneath the root selected by xtask's existing repository-root resolver. This honors the runtime source-root binding when present and the compiled project location otherwise. It does not infer a repository from the child working directory or change process-global TMPDIR. Running xtask from `rust/` therefore selects the same staging location.

The project root and scratch directory must be component-wise no-follow directories, owned by the controller UID and not writable by group or other users. A symlink or a child-writable directory is rejected, not repaired or accepted as a fallback. New scratch directories have mode 0755. Each executable still has its own temporary directory, mode 0755, and an immutable staged file, mode derived from the source's owner read/execute bits. Source retention, bounded no-follow reads, create-new publication, sync, digest/length/mode comparison, post-run identity verification and automatic cleanup remain unchanged. No candidate admission, evidence publication, signing or writable-copy rules change.

The transport fixtures need a socket inode for their special-member rejection checks. They do not use that socket for communication. They now allocate a six-character directory beneath project-local scratch, bind the basename `s`, and rename the socket inode into the evidence tree. Both locations use project-local scratch so the rename stays on the same filesystem. The finalizers still inspect the original evidence layout and must reject the special member while preserving a detached fallback.

Before allocating a socket directory, the helper validates the complete generated bind pathname with the standard library's `SocketAddr::from_pathname`. This applies the host's Unix-domain address limit, including space for its terminating NUL, without a Darwin-specific constant or a Linux fallback. A root that cannot fit fails with its invalid pathname in the error. Tests derive the boundary from the existing libc `sockaddr_un` layout and check the last accepted byte length, the first rejected length and multibyte UTF-8.

Regression verification retains the staging containment assertion and the two long-TMPDIR failures before implementation changes. The fixes must pass those same behavioral checks, a deterministic evidence path longer than the platform bind limit, selected-root staging and cleanup, and symlink/writable-directory rejection. Full supported-route results are recorded separately from focused tests; focused passes alone do not establish full-route acceptance.
