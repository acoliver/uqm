# UQM media and platform design audit

Source: `678f8c11defe28a85cfccac29899410209e9963c`. All repository paths and line numbers below refer to that commit. This is a static review of the pinned tree and its call sites. No builds, tests, gameplay, device or window probes were run. The proposed test gates are future work. No external publication or project source edits were made.

## Verdict

Give the application explicit owners for content, the display and input session, audio, and movies. The main loop, codecs, software renderer, and native adapters already run in Rust. The remaining C shape is most visible in the process registries, property-number APIs, mutable selected context, and separate init/uninit calls. Preserve the original file formats, pixel and sample math, frame publication order, and platform ABI at their boundaries. Replace the internal architecture around them.

The first failures to characterize are partial startup and teardown, a stale movie token stopping its replacement, the missing native joystick registration path, and malformed content reaching unchecked parsing. Audio and graphics need larger vertical changes, but neither needs new codecs, new raster math, or a new graphics API from a third party. Move the existing behavior to owners and prove it there before changing performance policy.

## Runtime and platform ownership

The composition root is `rust/src/main.rs:25-57,87-106`. It selects native or replay platform before even `--check-content`, sets up logging for normal runs, sets macOS QoS on the main thread, builds `Game` and `InputControls`, and installs the app input runtime. `rust/src/app/mod.rs:24` installs the runtime in the kernel. `rust/src/app/runtime.rs:15-31,39-70` starts services, starts the audio heart before kernel load, runs splash and campaign, then releases kernel state before subsystem teardown. Startup does base SDL and owner-thread registration, installs VFS, prepares directories, opens graphics and then starts input (`rust/src/mainloop/startup.rs:29-81,84-124,160-186`). Normal teardown is input, audio heart, graphics, dispatch, installed VFS, and game-thread bookkeeping (`rust/src/mainloop/teardown.rs:10-17`). Cleanup of game objects and context owners lives separately in `rust/src/game_init/cleanup.rs:6-42` and `rust/crates/engine/src/kernel/display.rs:33-56`.

**P1, lifecycle.** Startup returns a status after acquiring state. An input failure after display open returns to `app::run` before the normal teardown call. Graphics open and unrecoverable reconfigure call process exit inside the engine; mixer start can exit, a stream startup failure returns a status that `run_game` ignores, and the abort key calls `process::exit` from the input driver. `process::exit` bypasses Rust destructors; the registered C exit callbacks cover only what was explicitly registered. This is a static control-flow finding; real-device behavior was not tested. Keep process exit policy in `main` and return a typed outcome through modal and campaign boundaries. Use one acquired owner per completed phase and explicit shutdown where joins or publication errors need reporting. Tear down active movie/audio work and observation before tearing down the devices they use. Evidence: `rust/src/mainloop/input_driver.rs:43-53`, `rust/crates/engine/src/graphics/present.rs:218-244,264-273`, `rust/crates/engine/src/sound/audio_init.rs:42-82`, `rust/crates/platform/src/os/sdl.rs:35-62`.

**P2, capability split.** Engine host contracts are already pointed the right way: `Display` borrows layers, `Files` returns owning stream objects, `Clock` and `System` model different time domains, `Net` is a port, and `host/fallback.rs` provides test seams (`rust/crates/engine/src/host/display.rs:12-54`, `host/files.rs:12-73`, `host/clock.rs:12-65`, `host/system.rs:10-36`, `host.rs:5-34`, all beneath `rust/crates/engine/src`). But the `Platform: Send + Sync` singleton combines safe worker services with SDL polling, text, display creation, and game dispatch; the method types do not enforce the SDL owner-thread comments. `OnceLock` makes platform composition process-wide and fallback tests need process policy. `rust/crates/platform/src/host.rs:25-139` shows the actual replay boundary: OS display, filesystem, system and network remain native, native input polling and mixer output are suppressed, clock and clip audio are replaced. Engine replay pacing advances the clock and pumps decoded audio at the sleep boundary (`rust/crates/engine/src/threading/pacing.rs:197-270`). Keep the replay/test ports and the distinction between simulation ticks and OS deadlines. Hand the application a non-`Send` main-thread media session and small cloneable handles only where there is a worker or observer. A static factory or true process facility can remain global. Avoid a new service locator.

**Platform leaves.** `rust/crates/platform/src/lib.rs:11-51` owns install and default config path policy, which belongs at app admission. `system.rs:36-85,91-148` owns worker join, time and disk stream translation; preserve its real OS operations and return typed spawn failure instead of treating ordinary acquisition failure as an invariant. macOS `critical_timer.rs:27-85` supplies one-shot critical kqueue waits; `qos.rs:26-91` sets and reads back the calling thread class. Preserve these measured platform policies and keep their timers distinct from replay. `sdl.rs` is the adapter module root; `os/sdl.rs:15-50` and `sdl/display.rs:59-113` initialize SDL by separate routes. Use a single owner for SDL video, input and joystick handles, with renderer/window dropped before SDL. Keep SDL FFI inside platform; `sdl/macos.rs:40-85` is genuine Cocoa coordinate and calling-convention translation. `macos.rs:67-127,192-208` owns CoreGraphics observation and kqueue registration; `macos/directory_watch.rs:22-78` owns a watched descriptor and queue; `macos/sandbox.rs:20-39` is a child-launch facility. None of these belongs in game media state.

`rust/crates/platform/src/os.rs:1-38` marks the system-call boundary. Retain `OwnedFd`/`BorrowedFd`, borrowed directory-relative operations, the iterator that closes its directory, and typed `io::Error`. Keep raw descriptor numbers only at the child inheritance protocol boundary. `os/descriptor.rs:11-33` owns the inheritance guard, `os/fd.rs:16-59,74-101,124-201` owns descriptor operations and deadline I/O, `os/fs.rs:28-107,112-216` handles directory operations, `os/lock.rs:15-37` handles advisory locks, and `os/clock.rs:14-29` provides the monotonic deadline clock. `os/process.rs:11-139,156-243` handles PID, child state and platform inspection; `os/signal.rs:10-81` records signals and changes dispositions; `os/errno.rs:11-45` bridges the native per-thread errno cell; `os/stderr.rs:11-47` redirects a true process stream. Keep OS representations here. Group these around automation-facing capabilities when migrating the callers, retaining the process, descriptor inheritance, and deadline contracts. Review `before_exec` as a restricted child boundary, not a place to run arbitrary game callbacks. Runtime connections include `rust/src/automation/child_session.rs:32,71`, `artifact.rs:15,56`, `interrupt.rs:10`, `native_window.rs:344-355,1532`, and `native_isolation.rs:45` under `rust/src/automation`.

`rust/crates/platform/src/net.rs:5-19,53-176` uses owned sockets and a pending connect reply with a typed state enum. Keep those and the nonblocking behavior. The caller still gets a numeric `Connection`, the internal stream accessor assumes a ready connection, and dropping pending work need not interrupt the worker resolving or connecting. Decide whether cancellation means abandoning results or joining cancellable work; make invalid or pending operations explicit and keep the wire-facing game code separate. `rust/crates/platform/examples/platform_smoke.rs:10-35` is a useful independent adapter contract: loopback DNS, connect, WouldBlock, send, EOF. `rust/crates/platform/Cargo.toml:14-36` and `build.rs:1-10` distinguish bundled SDL from Unix system pkg-config and Windows dependencies. Keep a dependency/feature matrix for bundled and system SDL, default and no-default features, and debug-process. Verify whether the explicit probe is redundant with SDL dependency discovery before removing it. Preserve the installation diagnostic if it is the only actionable one. Native audio and display implementation details follow below. In the platform paragraphs, abbreviated paths are relative to `rust/crates/platform/src`; elsewhere they are relative to the named engine subsystem unless another root is stated.

## Content, settings, strings, and files

**P1, the catalog, settings, and assets have different lifetimes.** `rust/crates/engine/src/resource/index.rs:18-90,108-164,175-199` holds configured values and asset descriptors in one lazy mutex. Reads can recreate an uninitialized map, an unexpected file type asserts, and a string kind and `u32` encode several unrelated domains. `resource/settings.rs:9-50` is a zero-sized view of that same object and serializes sorted prefixed values through a `Dir`. `resource/cache.rs:1-16` is a loader, with no cache; callers own graphics and fonts. Runtime mounts directories and addon shadows (`rust/src/mainloop/dir_prep.rs:118,148-320`), enumerates base/addon indices (`rust/src/mainloop/options_abi.rs:8-46`), and installs menu and flight properties into the same map (`rust/crates/engine/src/input_port/sdl_input.rs:256-272`). Graphics, fonts, text tables, binary tables, conversation, SFX, music and video load against this catalog and a second ambient `io::content_dir()`. Existing mode/kernel owners retain the data they use; for an example spanning graphics, sound and table references see `rust/crates/engine/src/battle/ship_assets.rs:143-205`.

Split the immutable, ordered content catalog from mutable user settings and bindings. Resolve an asset to a typed descriptor and source, preserving base/addon precedence and diagnostics. Put strings and file names at their appropriate boundary instead of requiring `CStr` of every caller. Keep optional assets explicitly optional; report malformed required assets with kind, source and path in the error. Retain caller-owned lifetimes, and introduce a bounded cache only for measured repeated work. If shared, cache immutable decoded data by resolved identity plus relevant options and content revision; mutable canvases, palette versions and per-play decoder cursors have different lifetimes. Do not add a process-wide second asset registry. Delete the misleading cache facade when callers use the new catalog directly.

**P1, parser contracts.** `rust/crates/engine/src/resource/propfile.rs:19-106` has case-preserving callback parsing, `#` comments, prefix and a 255-byte cap; `String::truncate(255)` can panic where that byte splits a UTF-8 scalar. `resource/color.rs:6-132` handles C-style integer and color encodings; retain equivalent values and serialization for shipped inputs. Pin accepted grammar and fallback behavior to fixtures, including invalid values and trailing material, rather than assuming that a comment about `atoi` describes actual Rust parsing. `resource/mod.rs:12` keeps a C-string optional key alias. Replace that internal representation after migrating the actual content consumers.

`rust/crates/engine/src/strings/getstr.rs:28-185,218-312,372-429` walks header blocks and matching timestamp lines; text and binary use different contracts. Preserve leading/trailing whitespace decisions, line and entry caps, `#(NAME)`, optional clip path and timestamp columns, malformed timestamp disabling, NUL and absent-versus-empty distinctions, and wrapping indices where callers rely on them. The BINTAB all-ones marker and big-endian count/length fields are file representation. Its parser indexes raw words, computes an unchecked data slice, and splits unchecked lengths. `getstr.rs:635` characterizes rejection by panic; make malformed files a typed error and update that test deliberately. Decode structured entries with checked lengths and one validated buffer or owned slices. Keep `LoadedTextTable`/`TextEntry` retaining data and `ConversationPhrase` borrowing from the owner (`strings/owned_table.rs:34-61,71-119,132-172`, `strings/conversation.rs:8-29,58-69`). Replace `EntryRef` address identity where consumers only need an observation ID or an owner-plus-index; addresses can be reused after drop. `strings/sresins.rs:6-18` reloads/copies whole entries, suitable only where a detached value is required. `strings/unicode.rs:15-134` deliberately decodes/resynchronizes malformed input and maintains legacy prefix and character-class behavior. Keep that byte codec at the format or input boundary; use `str`/`char` for validated internal text where semantics match.

**P1, retained VFS behavior and seek.** `rust/crates/engine/src/io/mod.rs:19-51` installs a second process registry. `io/vfs.rs:49-101,143-177,244-277` retains the resolved host path and virtual path plus the shared mount table. Reads resolve against the current overlay; the host path can remain usable after unmount. Writes prefer the retained directory owner, with read-only/archive rejection. Mount order is numeric position, longest prefix, then creation order; reads fall through only for NotFound and listings de-duplicate. These are separate policies worth preserving (`io/vfs.rs:332-404,453-521,570-598`). Separate virtual paths from host paths instead of guessing from a list of top-level directory names (`io/vfs.rs:603-673`). Treat lexical normalization as a path rule, not a filesystem isolation guarantee. Snapshot the resolution inputs and release the table lock before disk I/O or decompression. Scope temporary graphic/font archive mounts to loading rather than a shared mutable mount point (`graphics/load.rs:144-178`). Preserve retained directory and stream life after unmount, writable config/save targets and overlay order. Do not let recycled `MountId` after `unmount_all` identify an unrelated mount.

`rust/crates/engine/src/io/zip_reader.rs:81-165,214-275,278-371` retains archive entry metadata and has two read paths. The reader eagerly reopens the package, decompresses and validates a full entry, and then serves a memory buffer; this also affects consumers that incrementally decode Ogg. Preserve integrity and error semantics before deciding whether to index/open once, bound buffering, or stream a large entry. `seek` allows positions beyond EOF, but `read` subtracts that position from buffer length. Standardize beyond-EOF read behavior and checked seek arithmetic. Keep `Read`/`Seek`/`Write` integration and fallible `finish`; scope the mixed read/write `host::File` requirement so a read-only stream need not pretend to write. `io/fixture.rs`, `io/vfs_tests.rs`, `io/vfs_stream_tests.rs`, `io/zip_reader.rs:448-625`, and `rust/src/mainloop/dir_prep_lifecycle_tests.rs` supply existing fixture and test seams.

## Graphics and presentation

**P1, retain pending work by construction.** `rust/crates/engine/src/graphics/state.rs:73-106,198-231` centralizes the renderer but hides it behind thread-local `RefCell`. Public ID operations still resolve through ambient state. `arena.rs:6-95` has typed generational image handles; `drawable.rs:21-66,361-400,506-578,718-744` wraps drawable/frame IDs with lease owners, and `font.rs:295-361,389-401,477-526` and `context.rs:53-132` do similar work. `context_store.rs:73-126,343-403` keeps selected state and retains targets, fonts and effect frames. These are meaningful improvements over untyped raw pointers. Keep typed stable identity where records need it, existing retained assets, and the useful `BatchGuard` and `BatchPause` scopes (`context.rs:148-164`). Prefer a renderer-owned store keyed by session-local handles, borrowed views for immediate work and owned references for work that crosses a frame boundary. Replace `FrameId`'s no-frame state with `Option` where a draw genuinely accepts absence; model screen target and drawable frame separately. Preserve intentional wrapped frame selection and `u16` behavior wherever it is observed. Remove manual lease counts or deferred deletes only after commands, context state, and retained captures express their actual ownership. Keep true affinity in the owner type, not a bare ID plus an ambient lookup. Replace the `menu.rs:16-195` free-function selected-context facade by migrating whole caller flows.

**P1, command order is a compatibility contract.** `draw.rs:5-6,62-90,172-215,262-288` queues screen work and draws to RAM frames immediately. `state.rs:144-177,198-231` stages commands outside the borrow, installs scissor changes, and on capacity resets batching and drains without the final swap. `dcq.rs:37-105,141-218` keeps FIFO visibility across nested batches, callback/reconfigure entries, and deferred image or glyph release commands. `state.rs:441-493,537-542,749-765` distinguishes normal flush, drains and purge, and runs callbacks/video mode changes outside the draw-state borrow. Reconfigure can itself present, so `skip_swap` suppresses the drain's final swap, not every possible presentation. `rust/src/mainloop/input_frame.rs:29-68` drains then requests a swap at nested loop entry and after the complete callback, even at termination. Treat frame commit, queue drain, capture/copy readback, mode change and resource release as named operations. Snapshot clip, mode and palette at the same boundary as today; characterize live image mutation before substituting immutable snapshots. Keep capacity behavior until tested at the boundary, and test callbacks that append work or enter another loop. `state.rs:254-258` only clears screens and takes display; include unfinished batches and pending callbacks in renderer shutdown policy instead of assuming the next initialization will clean them up.

**P2, raster formats, loaders and caches.** `geometry.rs:1-119` carries i16 legacy coordinates and integer draw modes. Use types for blend mode, scale policy, alpha and target; retain integer rounding, clipping and wrap behavior where game pixels or collisions differ. `bbox.rs:14-95,270-349` tracks dirty regions and clipped endpoints; `intersection.rs:230,424-453` is gameplay collision, with tests for fixed-point and previous non-colliding endpoint (`intersection.rs:519-669`). Keep that separate from render optimization. `canvas/mod.rs:18-103,565-588`, `canvas/raster.rs:12-245`, `canvas/rotate.rs:25-40` and `canvas/scale.rs:163-378` give software pixel formats, compositing, rotation and interpolation; preserve indexed palettes, masks, color keys and native-byte conversions rather than forcing all formats to RGBA internally. `canvas/png.rs:10-26`, `load.rs:41-136,188-307` implement PNG, animation scanning, package/direct opening and hex glyph names. Keep scan and glyph compatibility at decoding, and separate decoded assets from renderer allocation. `image.rs:21-48,79-86,98-176,194-202,271-407,581-647` retains normal, filled, scaled and mipmap state plus palette version and hotspots; the screen-copy path documents deliberate non-invalidation. Use explicit source revision, palette version and scale/fill parameters for derived caches, preserving that exception if it is observable. Do not combine resource lookup caching with derived image caching. `font.rs:17-43` and `draw.rs:400` connect bitmap glyphs and text measurements; test glyph alpha backing, truncation, alignments and missing glyphs. `batch.rs:7-119` already gives typed drawing and retained stamp owners; keep it and preserve submission order.

**P2, the compositor has two owners today.** `rust/crates/engine/src/graphics/present.rs:39-144` suppresses unchanged frames and orders main screen, clipped transition, black or white fade, then an un-faded main-screen system box. `screen.rs:9-65` holds extra-screen and transition copy semantics; `colormap.rs:50,158-365` handles byte palettes, wrapping tick interpolation and immutable versioned map snapshots. `palette_cycle.rs:7-43` is a retained binary-palette consumer. `highlight.rs:85-175,362-373,503-550` maintains flash/overlay captures and scheduled state, and `flash_math.rs` implements integer fraction and cache rounding. Keep the RAII owners and clock-driven math; migrate scheduled work from a supplementary thread-local registry to the render session. `surface.rs:12-47,89-157` already owns planet source surfaces and rescaling; separate the generation-facing API from display state without losing its owner.

In `rust/crates/platform/src/sdl/display.rs:134-236,255-286,327-386` SDL clears black, scales/uploads layers, applies scanlines after composition, records diagnostics, performs selected readback before the actual present, then swaps. The upload allocates a texture per layer; preserve scale and color conversion order and use reusable scratch and textures only after byte and allocation profiling. `graphics/software_scalers.rs:23-329` and its `advanced.rs`, `biadaptive.rs`, `hq_rules.rs` and `tests.rs` cover the integer algorithms and lookup rules. SDL xBRZ is an additional mode; do not conflate it with asset mipmap or movie scaling. SDL display reconfiguration keeps the window (`sdl/display.rs:456-483`), and native positioning is proof-specific. Treat old CLI numeric flags and unsupported gamma (`present.rs:288-294`) as admission or reported capability. Keep engine ownership of composition policy and platform ownership of texture upload/window lifetime, with a single typed frame publication protocol. `graphics/presentation_diagnostics.rs:7-42` and `presented_frame.rs:6-41` should remain observation data and validated PNG encoding. `present.rs:92-101` still calls the capture decision inside the graphics borrow through `Display::present`; keep the decision restricted to detached metadata or move it to a safe boundary. Preserve the distinction between actual composed readback, internal canvas capture and independent OS window evidence. `rust/src/automation/input_ffi.rs:409-446` adapts these observations today.

## Input and native event admission

**P1, native joystick ownership is missing from the live route.** `rust/crates/platform/src/sdl/input.rs:10-21,24-91,105-126` translates events and enumerates device names but does not open and retain joystick devices or describe axes, buttons and hats. `rust/crates/engine/src/input_port/sdl_input.rs:250-298` logs the names; it never registers those devices in `VControl`. The native adapter forwards SDL event `which` as `port`; `vcontrol.rs:140-179,201-259` expects registered slots. The demonstrated joystick event test constructs its own registry (`sdl_input_tests.rs:170-214`). No live registration or `SDL_JoystickOpen` was found in the pinned Rust tree. Establish this with an SDL virtual device test before changing policy. Put owned SDL handles and the mapping from instance ID to configured slot in the main-thread adapter. Deliver typed attach/detach and event data, including device capabilities. A detached device must release its active targets and not leave a held axis or menu pulse. Preserve persisted slot naming even if native IDs are transient.

**P2, there are two input owners and two binding readers.** `rust/crates/engine/src/input.rs:9-53,57-120` gives the kernel an `InputRuntime` and passes typed callbacks with `Cx` and observer access. `input_port/session.rs:11-66` retains hooks with callbacks released before user work, and `controls.rs:11-68,72-175` owns frames and state with thread affinity. Keep these rather than returning to untyped callbacks. Driver state, binding configuration, mouse and character mode remain in an independent process mutex (`sdl_input.rs:64-142,256-272,308-342,395-410`). Make binding tables and live state members of the retained input session. `gesture.rs:14-97`, `keynames.rs:141,624-645`, `templates.rs`, `keyboard.rs:13-78`, `joystick.rs:31-110,120-247` and `vcontrol.rs:30-114,223-274` already separate gesture grammar, names, binding dispatch and state. Retain this structure and bound indexes on construction. SDL key values and hat masks are justified at adapter/configuration boundaries. Replace mode-facing array indexes, packed count/start words and numeric template/control/alternate arguments with typed actions, held counts and edges; retain any battle bit encoding at its game boundary. Reuse a single parsed binding store for menu interrogation and automation (`menu_binding.rs:29-74`, `sdl_input.rs:179-222`), including the first missing menu alternate terminating the scan. A rebind currently removes the previous binding before polling and persists the detected gesture without checking whether `bind` succeeded (`sdl_input.rs:487-531`). Use a transaction with explicit cancel/quit and update persistence only when a gesture was accepted, with an intentional compatibility test for any behavior change.

`rust/crates/engine/src/graphics/events.rs:11-27` polls platform events, sends input to the driver, records window diagnostics, and handles quit and expose. Replay bypasses the native path. `rust/src/mainloop/input_driver.rs:5-39,64-107` processes async work and events, utility keys, observer admission before and after update, menu audio, the owner hook, the callback, then frame completion. `rust/src/mainloop/input_abi.rs:28-53` snapshots before and after clearing frame edges; `input_port/frames.rs:46-68,83-225` implements independent and combined repeat and wrapping tick subtraction. Preserve exact sample and observer order while moving the event pump into the application media session. Keep `HostEvent` a data seam (`rust/crates/engine/src/host/event.rs:5`); distinguish quit, expose, device and text events from formatted diagnostic payloads. The current tests cover two owners, reentrancy and callbacks, wrap/repeat, deferred text-mode changes and NumLock/keypad behavior (`rust/crates/engine/tests/input_controls.rs:13-88`, `input_frames.rs:10-70`, `input_port/session.rs:88-153`, `input_port/sdl_input_tests.rs:97-306`). Extend those tests to interleaved driver sessions, actual device mapping, remapped alternates, injection rejection and a stopped/reentrant nested input loop. Extract the app's cross-subsystem modal/pacing operations from the input port only when their callers migrate too.

## Sound, playback clocks, and device ownership

**P1, one owner must control callback, decoder and device lifetimes.** Under `rust/crates/engine/src/sound`, `audio_init.rs:15-81` starts a fixed 44.1 kHz 16-bit stereo mixer. `stream.rs:47-77,709-749,754-826` installs source handles in process-wide slots, starts CPAL output and a decoder worker in native mode, or an owned clock accumulator without a worker in replay. Shutdown takes replay state, stops the output, then signals/wakes and joins the decoder worker; the outer function then calls `mixer_uninit`. That function clears only the mixer state, while source and buffer pools have independent statics (`mixer/mix.rs:18,78-87`, `mixer/source.rs:102-176`, `mixer/buffer.rs:101-188`). Prove repeated start/stop, stale events and outstanding assets before relying on application restartability. SFX, stream, track, music and options also have process state (`sfx.rs:57`, `stream.rs:68-71`, `trackplayer.rs:136`, `music.rs:46`, `control.rs:54`, `volume_globals.rs:17`). A single `AudioSession` should own the mixer, typed voices, producer/consumer endpoints, clock policy and all join handles. Keep native `cpal::Stream` on its owner thread, stop callback access before releasing mix state, signal and join the producer without holding a lock it may need, and drain or invalidate completion tickets. Map no device to an explicit silent policy and test whether its notion of completion matches live behavior; keep replay independent of OS audio.

A second path starts lazily for movies. `sound/audio_device.rs:14-103` wraps whole PCM clips and synchronous reply commands; `rust/crates/platform/src/rodio_device.rs:14-68,74-136` uses its own static sender/thread and sink map, and stops/join only on explicit shutdown. Normal app teardown has no `audio_device::shutdown` call, and the audited callers of that helper are tests. A movie drop normally stops its sink; that does not join the rodio worker. `rust/crates/platform/src/audio_output.rs:10-71` reports thread spawn, not successful device open; the worker can idle without a device. The callback panics are contained and output is silenced (`audio_output.rs:75-86`), but the engine pump allocates a byte buffer and converts into another vector every 1024 frames (`stream.rs:764-783`) and the mixer takes locks (`mixer/mix.rs:324-402`). Keep device thread affinity and testable sinks. Move PCM preparation and lock-taking off the callback path, preallocate, and measure callback overruns. In the first ownership change, join both existing adapters together; an eventual single device path should mix embedded movie PCM with the shipped volume/pan/resampling and completion policy instead of changing it by accident. Verify device negotiation and no-device behavior before removing either backend.

**P2, decoded assets, voices, and stream state should be different types.** `sound/heart_ffi.rs:22-80,483-596` is a safe Rust facade despite the name. It dispatches by extension over bytes, eagerly decodes bank entries and creates mixer buffers, or loads a decoder and allocates 64 buffers for music. `owned_bank.rs:11-85` retains a bank for a clip, but the bank owns `SoundSample`s tied to device-side buffers. `resource_types.rs:9-39` uses a drop wrapper over `MusicRef`, an `Arc<Mutex<SoundSample>>` with pointer identity exposed to records (`types.rs:162-238,353-409`, `rust/crates/engine/src/battle/ship_assets.rs:204`). Replace it with immutable PCM for short effects, a reloadable source for long streams, and a session voice with an independent playback cursor. Keep wrapped bank selection where intentional. Compare the alternate loading/destruction route through `fileinst.rs:33-86`, `sfx.rs:278-292` and `music.rs:246-287`; the file load guard is scoped RAII, but its shared current filename is an inherited restriction, not necessary for independent decode jobs. Replace the integer glue in `heart_ffi.rs:242-479` when callers migrate to typed channel/music/speech operations. Keep policy from `control.rs:66-169`, `sfx.rs:65-263`, `music.rs:50-234,296-317` and `volume_globals.rs:6-30` covering priority, positional gain, fades, stop, pause and requested/effective options; characterize priority inputs that are currently ignored rather than silently assigning new behavior.

`mixer/mod.rs` exports `buffer.rs`, `source.rs`, `mix.rs`, `resample.rs`, and `types.rs`. `types.rs:74-174` already names formats, properties, states and quality, but the property API and reusable `usize` slots reproduce an OpenAL-style model. Prefer typed methods and a session-owned registry with IDs only where work outlives a borrow. Retain sample order, queue progress, resampling phase and gain arithmetic (`resample.rs:17-221`). In `stream.rs:162-409,831-893,897-1196`, source queue, decoding, pause/seek, tags and deferred callbacks implement different lifecycles. Retain the rule that callbacks which can call back into audio are executed outside the stream state locks. A conversation-owned sequence in `trackplayer.rs:41-165,261-445,463-695` lends decoders and advances pages on processed buffer tags. `trackplayer_subtitles.rs:7-33` copies owned observation snapshots while state is locked. Keep snapshot semantics and use a session page ID rather than address-derived identity. ## Video

**P1, a playback token does not own the playback it stops.** `rust/crates/engine/src/video/legacy.rs:19-81,182-205,210-274` puts player, flags and embedded-audio handle in global `CURRENT`. A token owns optional music/speech resources, but its queries and destructor address whichever playback is current. Start A, start B, then drop A: A's destructor calls stop on B. The existing replacement test (`legacy_tests.rs:103-121`) explicitly asserts that dropping A stops B. Change that assertion with the ownership fix; this is an intentional correction to the behavior recorded by the existing test. The `stop_player` method called by `rust/crates/engine/src/configuration/runtime.rs:74` and `kernel/display.rs:53` clears only the picture. Reconfigure/teardown may therefore leave the embedded clip active until the token drops. Playback runs graphics work and can start device operations while the global current lock is held. Replace it with a non-`Send` movie session or an explicitly identified running instance. Host it at the mode/app boundary, inject clock, sound and frame output, and stop exactly the session that created each voice. Releasing a superseded token must be harmless. No separate video thread is required by the current scheduling model.

`rust/crates/engine/src/video/descriptor.rs:10-67` parses `3DOVID` with empty colon fields and a legacy numeric loop sentinel; `files.rs:6-27` opens `.duk`, `.frm`, `.hdr` and `.tbl` through supplied files; `video/mod.rs:60-105,226-343,445-512` defines validation, byte-level headers, delta tables and frame data. `decoder.rs:155-303,423-581` validates component data, decodes format revisions, and converts pixels. Preserve component ordering and codec behavior, and share validated container bytes and offsets with DukAud where practical. Today probe and start each open the picture components, and embedded audio reopens `.duk/.frm` then buffers decoded PCM (`legacy.rs:95-162`). Load once at the movie boundary and create independent consumers from shared data. Pin accepted DUK layout, endian fields and pixel conversion with shipped and corrupt fixtures. Keep file format and fixed pixel layout representations at that boundary.

`player.rs:120-223,285-317` models stop/pause/resume and computes due frames from host time, including skipping late frames and restarting loops at zero. The descriptor's non-sentinel frame currently means a boolean loop; it does not select that nonzero frame. `VideoPlayback::seek` is a no-op, and the optional external audio and speech tracks are loaded/retained by the token; that alone does not demonstrate they are started. Characterize these against shipped assets and modes before enabling any new behavior. Keep clock progression, terminal behavior, and centered/blit-clipped pixels (`player.rs:323`). `rust/crates/modes/src/front_end/intro.rs:158-169,180-245` selects slide or movie resource and runs the input/playback loop; `front_end/fmv.rs:20-39,79-87` routes ship spins and intro/ending through it. Preserve the game flow and skip behavior. The production `start_player` uses the canvas path; setters for direct-window and optional scalers have only test call sites found at the pin, and `lanczos_scaler` is stored but not applied by the frame step. `player.rs:225-269`, `scaler.rs:24-204`, and `rust/crates/platform/src/sdl/display.rs:389-438` are candidate seams to delete or consolidate after checking supported presentation modes. If direct output remains a product mode, route it through the same publication and observation boundary. Retain `legacy_tests.rs`, `playback_tests.rs`, descriptor/decoder unit tests and the shipped-logo and ship-spin fixtures while removing the experiments they alone exercise.

## Logging

`rust/crates/engine/src/logging.rs:1-37,40-90` makes a throwaway `CString` and prints independently of `log_abi.rs:9-63`, whose 255-byte/NUL output rule and exit-box flags are another Rust-only shim. `bridge_log.rs:9-47` creates a fixed current-directory diagnostic file, holds a process mutex and flushes on each write, including media paths. The format is documented in `dev-docs/rust/howloggingworks.md:1-12`; no executable reader for that file was found in the pinned Rust sources. Check external tooling before removing a documented artifact. `rust/src/mainloop/logging.rs:16-50` creates the CLI log for tracing, then `startup.rs:52-61` redirects stderr by opening the same path through `rust/crates/platform/src/os/stderr.rs:11-47`. Two writers and open modes make ordering/truncation a risk. The test in `mainloop/logging.rs:56-62` only constructs a path. Establish one application writer/sink and one filter; preserve `log` events via the subscriber bridge, use typed diagnostics for instrumentation and keep native stderr capture only if CLI compatibility requires it. Leave the composition root free to install a process-wide subscriber. Finish or flush it after the workers. Keep structured presentation observations independent of text logs so native proof does not depend on debug strings. Migrate the remaining user-facing exit messages and compatibility artifacts before deleting `logging`, `log_abi`, and `bridge_log` shims and stale C-port comments.

## Vertical implementation units and test gates

Each unit changes a live path through all its callers and removes what it replaces in the same change. Tests below name executable behavior to preserve or a defect to correct. A change to a malformed-data, stale-token, or missing-device case must be recorded separately from preservation of shipped behavior. Use pinned fixtures and headless parity for deterministic contracts. Use the native observation path at subsystem integration or to investigate a discrepancy; internal captures and an SDL dummy window cannot establish real-window output. None of these tests was run for this audit.

1. **App lifecycle and platform session.** Move native/replay composition, SDL admission, worker-safe services, startup error and quit policy into owned application phases. Migrate startup, teardown, engine host callers, test adapters and tools using platform installation. Delete duplicate base SDL init and manual installed-service teardown paths as their owners take over; retain genuine OS exit registration only for true process facilities.
